# AGENTS.md — rules for changing this Neovim config

This repository is a Neovim configuration, not a library. It is loaded by an
editor at startup, so a syntax error means the user's editor does not open.
That fact drives every rule below.

## The one rule that matters

**Never call `vim.keymap.set` for a global keymap.**

```lua
-- NO
vim.keymap.set("n", "<leader>ff", function() ... end)

-- YES
function M.setup(R)
  R.map({ lhs = "<leader>ff", rhs = function() ... end, desc = "Find file", cat = "Find" })
end
```

`lua/config/registry.lua` is the single source of truth. One declaration feeds:

1. the real keymap (`R.apply()`),
2. which-key's group labels (`R.group`),
3. `:HelpMe` — the in-editor cheat sheet,
4. `KEYBINDINGS.md` — generated by `scripts/gen-docs.lua`,
5. a duplicate-key audit (`:Lua dofile('scripts/health.lua')`, or `make verify`).

A keymap added any other way is invisible to all of that, and the help starts
lying to the user. There are exactly two documented exceptions, both inside
plugin `config` functions, both commented in place: Tree-sitter text objects
(operator-pending objects the registry cannot express) and multicursor keymap
layers.

## File ownership

| Path | What goes there |
|---|---|
| `lua/config/*` | core behaviour, options, autocmds. Change rarely. |
| `lua/config/registry.lua` | the API. Keep it small and dependency-free. |
| `lua/keys/<area>.lua` | keymaps + user commands for one area |
| `lua/plugins/<area>.lua` | lazy.nvim specs for one area |
| `lua/help/*` | the help windows |
| `scripts/*` | docs generation, verification |
| `extras/*` | terminal, tmux and Neovide settings |

**One plugin, one spec.** `snacks.nvim` is configured only in
`lua/plugins/ui.lua`; `mini.nvim` too. Two specs for one repository means
whichever loads last silently wins, which is a bug that only shows up months
later.

## Hard rules

1. **Every file must parse.** `make verify` first, then start the editor.
   A broken file in `lua/plugins/` prevents startup even though the plugin
   itself is fine.
2. **Guard every optional dependency.** `pcall(require, "...")`, and tell the
   user what to run when it fails. The editor must open even with zero plugins
   installed (first launch clones them).
3. **Never touch the user's toolchain.** No `dotnet` upgrade, no `npm install`
   anywhere (Node tools go through `pnpm add -g`, which shares one store), no
   `sudo` outside `install.sh` and only for the package manager. If a binary is
   already on `PATH`, use it instead of installing a second copy.
4. **Platform differences go in `lua/config/platform.lua`.** Do not scatter
   `vim.fn.has("mac")` through the config. Cmd exists only on macOS; the
   registry binds the portable fallback elsewhere.
5. **Idempotent installers.** `install.sh` and `install.ps1` are re-run by
   real people after failures. Every step checks before acting, and an
   existing config is *moved* to a timestamped backup, never deleted.
6. **Comments are for the reader who has never used Vim.** Explain *why*
   (`-- Cmd+W closes the tab, like VS Code`), not *what* (`-- close buffer`).
   This config has one audience: a competent developer who is new to Vim.
7. **No new plugin unless it replaces something or is unavoidable.** Every
   spec is a maintenance contract. Prefer what Neovim 0.12 already has
   (`vim.lsp.config`, `vim.hl`, built-in `gc`).
8. **Pin only for a reason.** Pin a major version when the next one is a
   breaking rewrite (`blink.cmp` 1.*), and say so in a comment.

## Verification before you claim success

```sh
make verify        # headless: plugins, syntax, registry, commands, LSP, DAP
make docs          # regenerate KEYBINDINGS.md; fails on duplicate keys
make format        # stylua
```

If you added a keymap, `make docs` must produce a diff. If you added a
command, it must appear in `:HelpMe`. If you added a plugin, `:Lazy` must show
it installed with no errors, and `make verify` must still pass.

## Style

- 2-space indent, `stylua` formatted, no tabs.
- Lua 5.1 compatible (LuaJIT): no `goto`, no integer division, no `//`.
- One concern per file; long files are a smell.
- British/plain English in user-facing strings; the user is a beginner, not a
  Vim historian.
